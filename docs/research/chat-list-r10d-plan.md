# R10D：普通 ChatGPT 历史列表与可达恢复

从本地`7161b8d`继续[完整计划](../FULL-REPLICA-PLAN.md)，CI/push暂停，先固定版取证再实施。本批目标是让真实服务器历史可从侧栏选择并进入已接详情读取，不将内存记录当重启后的服务器列表。

1. 核普通列表producer、能力门控、flat/includeProject输入、query serializer、分页和UI状态；以精确资源/UTF-16切片留证，不借归档页资格。
2. 专用受限GET，复用当前身份/路由/网络政策与有界读；锁定20条普通列表query、safe offset、错误/取消/晚身份，零CLI/模型写。
3. 读取、分页、失败重试与内存/服务器ID合并接侧栏；点击服务器记录进入真实/c/详情，保晚回、原草稿、导航guard与当前请求身份。
4. 用有意义分页/取消/重试/跨owner和实际App/sidebar回归验证，再做TSC、相关Rust及同源码构建，较大阶段本地Lore提交。

假设与缺口：本批采用源普通flat默认false，不伪造项目目录或权限；source include=true时hide_snorlax=false，false时省略，expand=false仍序列化。源门控、项目/星标/原生线程的完整混排与刷新语义仍须继续补证；未证不编造。列表total不能从可见条数反推，消息cursor与列表offset分开。

服务端列表可达不等于上次窗口地址/草稿/图持久化、动态消息分页或远端SSE恢复已完成。真实账号/模型、原生GUI/IME和同环境官方像素仍须独立验收；当前计划不代表已执行或通过。
