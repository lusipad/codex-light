承接本地`cbcfbe4`及[完整计划](../FULL-REPLICA-PLAN.md)，不缩减14批范围。CI与推送继续暂停。先核固定官方26.1111.2228.0的历史查询、详情图、当前节点、路由及恢复，再实施；本轮重新读取安装版本仍相同，尚未重新计算整包哈希。

## 假设与未知

- 服务端历史是权威数据，本地内存列表不能代表重启恢复。当前controller只有内存记录，冷路由没有真实详情加载，此事实可直接从当前源码验证。
- 历史加载不得调用CLI thread/resume替代。列表/详情具体路径、查询参数、项目与临时会话规则须先以固定源producer确认，不套用归档页门控。
- 服务详情可能包含分支和非文本节点；不能按对象枚举或时间排序自行重建对话。主路径、下一轮parent与未支持节点应按源规则保留，缺证不发后续请求。
- 读取失败、旧响应、账号/host切换不覆盖已有流、用户新草稿或当前页面。真实账号/付费模型和用户配置不用于测试。

## 顺序与成功条件

1. 查清官方列表与详情producer、schema/分页、图与当前节点、路由恢复输入，记录文件哈希和UTF-16原片段 → 核片段与固定包一致。
2. 复用现有身份/routing/有界HTTP/取消，新增最小真实读取入口 → 隔离fixture覆盖请求、错误、身份变化、取消和不执行写操作。
3. 按源图规则解码和接主窗恢复/侧栏；保留独立草稿与流生命周期 → 真实controller/App回归覆盖分支、缺节点、晚回、跨账号和恢复后接续parent。
4. 冻结当前单元，完成相关前端、TSC、Rust和原生编译，记录限制并本地Lore提交 → 无新依赖，无托管CI/push；GUI与同环境官方像素仍须独立证据。

这份计划不是通过记录。实际发现、已实现范围和未完成恢复能力分别记入R10实施备注及16.23A；持久图、流恢复、发送存在性核验等不能因只读详情成功被标为完成。
