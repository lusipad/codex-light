## 2. 路由和页面形状

基准路由 `/settings/local-environments`。gate `375130565` 打开且local host时，空search或 `view=personal-vault` 可replace到 `/settings/codex-cloud`（personal-vault转换为tab）；对应环境内容也可使用worktrees标题和environments tab。包内有这个分支不证明当前账号已启用，不能强开gate。

常规内容先列**全部真实已登记项目根**，不是仅active cwd。标题“选择项目”，右侧“添加项目”；每项目环境可展开，祖先配置作为“继承环境（{count}）”单独呈现。无项目/加载失败/重试独立状态。项目label优先真实名称，其后路径basename/原路径，不能按同名合并身份。

## 4. 真实发现、选择和保存合同

固定宿主339 `lR`：从workspaceRoot向上查 `.codex/environments/*.toml`，最多50层，遇真实Git仓库边界停止；目录内TOML按名称，结果以默认environment.toml优先、距离近优先、路径排序。保留parse-error条目，不因错误悄悄消失。不要扫出仓库外的任意祖先；符号链接/路径边界按现安全约束保留，不以放宽路径来实现发现。

默认选择N0a：成功的environment.toml优先，其次成功项，再首项；新文件名F0a先environment.toml，已占用时environment-2.toml递增，**不覆盖既有default.toml或同名配置**。

工作区选择存 `local-env-selections-by-workspace` persisted atom，key为 `${hostId}:${normalizedWorkspaceRoot}`；显式null与尚未选择不同。V0a在完成真实list后校验旧选择，错误项不生效；不同host、根、大小写等路径等价规则需与现有路径工具一致。具体missing修复策略与有意“无环境”不能混淆，不能总自动改为默认。工作树选择另用真实 worktree scope Git config `codex.localEnvironmentConfigPath`，无选择标记 `__none__`，不是写全局Git config。

表单序列化 `ut/dt/q` 证实：version>=1、trim环境名/动作名、setup始终保留、cleanup仅有内容才输出、平台仅非空覆盖输出、actions成对name/command；全空动作行省略，不完整行阻止保存。命令/脚本文本不得通过split/join意外改坏换行和引号；官方生成文件有autogenerated头。解析会trim生命周期脚本、过滤没有有效name/command的原始action，但不能自动重写用户损坏文件作为“修复”。

保存yt：先字段校验，传configPath、expectedRevision、hostId、raw；冲突不更新成功状态；落盘成功后invalidate真实list/read，并选择保存的配置。selection-failed必须单独报告“已保存环境文件，但无法选中它”，不能冒充文件没保存或环境已激活。现expectedContent精确原文比较可保等价冲突保护；若增revision用宿主真实hash，不在前端猜测。外部写与最终rename间仍有竞争窗口，不能宣称跨进程原子CAS。

离页/返回/切项目/切配置要保存或明确丢弃草稿；官方存在unsaved-changes dialog。连接重启/旧读取不得覆盖另一项目或正在编辑的草稿。

## 5. 工作树 setup 真消费者与最小失败模型

固定worker `EX(create-worktree)` 已证完整消费者，不仅文案：

1. 复用Git创建工作树后，E0将选中环境映射到新worktree的对应相对路径；必要时有受约束的未跟踪环境文件复制策略，已跟踪但新worktree不存在时不擅自拿源文件覆盖。先存worktree级选择key（或__none__）。不能把相对路径直接拼接到任意目标，复制必须校验真实边界/regular file。
2. 没有环境选择则setupResult=null；选中环境解析失败默认create失败，只有显式allowSetupFailure才保留工作树并返回setupError。不能默认忽略失败启动后续聊天。
3. `_g→_E` 取当前平台非空setup覆盖，否则default；无脚本可空操作。执行cwd是 `worktreeGitRoot + environment.cwdRelativeToGitRoot`（项目子目录场景不能一律用源码cwd）。注入 `CODEX_SOURCE_TREE_PATH`（源工作区路径）与 `CODEX_WORKTREE_PATH`（新工作区路径）。注意变量名是SOURCE_TREE，不是自行命名的SOURCE_WORKSPACE。
4. 非Windows用bash；Windows识别真实PowerShell/pwsh并按实际可用shell回退cmd/其他。写临时脚本及wrapper，捕获执行前/成功后环境；执行shell脚本保持其真实语义，不简单拼一行终端文本。runner等待进程退出并收stdout/stderr；取消kill、非0/信号/异常均failed，临时文件在finally清理。
5. setup succeeded后保存shellEnvironment差量到工作树；失败不把半成品环境传播为成功。包装变量/路径等不应进入保存差量。官方返回setupResult含cwd、scriptPath、status、startedAt/finishedAt、error、log；运行结果和created-worktree结果有区别。

本阶段最小实现以**现有Git/worktree命令 + 独立小型setup runner + 现终端/进程基础设施**完成，不引入新框架/依赖。可扩 `git_worktree_create` 参数/返回结构或同链受控续步，由主代理定；所有真实创建入口必须消费同一选中环境和结果，至少覆盖App默认worktree、移动/新worktree和WorktreesView，不能只在某一个按钮fixture里接通。

默认setup失败应可见且阻止依赖成功的后续会话启动。已经创建的worktree要报告真实路径/状态，允许明确重试/保留，**不要自动递归删除用户可能已改动的工作树**；若无法完整复制官方rollback行为，记录差异。重试前重读配置/标识，防止旧定义或取消后重复执行。执行命令来自用户配置，审批/信任和真实创建授权沿既有交互，设置保存本身不触发脚本运行。

环境变量捕获/跨终端应用若本阶段工具不足必须明确列未完成，不能仅传两个CODEX变量就宣称官方setup环境继承全部一致。实际Windows shell可用性、账户环境、进程树取消和原生输出流仍需隔离实测。
