## 当前源码问题

以下为调研时源码观察，不声称已经由真实 PTY 复现：

- `src/components/TerminalDock.tsx` 异步注册 `terminal:data`，创建/附着 effect 未等待注册完成；首次创建响应的 `replayLog` 为空。监听前到达的首段输出存在丢失窗口。
- `src-tauri/src/terminal.rs` 附着时克隆 buffer，实时数据仍可同时发送；前端直接写实时数据，再写整个快照，没有共同水位，存在重复或倒序窗口。
- Rust 对每次读取块独立调用 `String::from_utf8_lossy`；合法 UTF-8 字符跨块时会变成替代字符，损坏也进入回放 buffer。
- reader 在线程中启动后才向 session map 插入对象；快速退出可能先 remove 后 insert，遗留已退出会话。旧 reader 的退出移除也没有实例 generation 检查。
- 现有终端回归覆盖生产前端回调和静态接线，不覆盖真实 PTY 输出、读取分块、快照/实时事件交叉或快速退出。

## 拟实施数据合同

1. 完成事件监听注册后才能创建/附着终端；注册失败可见，不以固定延迟推断就绪。
2. 后端每个输出实例有 generation，快照与实时事件共享单调水位。前端暂存 attach 期间事件，恢复快照后只合并其后的数据，并丢弃旧 generation。具体字节/序号表示由实现确定，不能依靠文本相等去重。
3. 流式处理 UTF-8：保留不完整字符至下一块，EOF 决议残留。ANSI 和控制字符按原顺序透传，不按行重写输出。
4. 会话注册、启动 reader、退出清理具有明确顺序；旧 reader 不能移除新实例。短命进程仍交付尾部输出与退出，不留下可写的幽灵会话。
5. replay 上限明确标注为有界历史，不声称恢复无限输出；裁剪必须维持有效字符边界和正确水位。
6. 隐藏/切标签/卸载与重新附着不重发已投递命令，输出不可跨 session 混入。恢复输出不能触发终端生成的输入重新发往 shell。
