### 主区与 Windows 壳修改前合同

来源补证保存在 `.ref/parity/01/whole-page/reference/layout/report.md`。普通 Codex 的 `605278.9a7ad6f681.js::eq` 不传 `homeComposerMode`，因此 `634175.4437e0034c.js::eD` 使用非共享布局。按官方 16px 根字号，主区上内边距 24px，标题区与 Composer 区同为 grow/basis-0，标题区下内边距 96px，Composer 内容顶部 6px、底部 16px。两区最小高度取实际内容。标题外层最大 768px，左右 20px；Composer wrapper 最大 768px，左右 16px。标题为 28px、1.2 行高、普通字重及正常字距。项目名使用点状下划线，偏移 4px。

同版 `499225.6d2e47bea2.js::ty` 与 `0b44dcd83d3a.css` 证实 Windows 应用菜单顶条使用 height-toolbar-sm，当前 token 为 36px。主工作区 toolbar 在 Electron 使用全局 46px；52px 覆盖属于 browser 专属分支。当前实现分别为 54px 和 55px，需在统一壳中修正并回归受影响页面。普通 Electron 未定义额外 thread-body-inline-padding 时使用上述 wrapper 缺省值，不套用 browser 或 Workspace Agent 空态的额外宽度。

权限草稿键与默认模型的 cwd 也必须与显式无项目状态一致，不能仅修标题。对应新增回归已复现旧权限槽串用。技能来源经后端和自动补全过滤核对，已安装项来自全局 CODEX_HOME，无需清空全局能力。

### Composer 输入外观修改前合同

普通首页保持上方 utility rail 与下方输入 body 分层。补证见 `reference/layout/composer-report.md`。可见 body 的普通变体使用 22px 圆角、零边框，阴影归 body。深色为 inset 0 0 1px 0 #fff3，浅色用 elevation-composer；主题背景从真实外观 token 读取。当前双重边框与外框阴影需要移除。

默认 multiline 空附件区保留上下共 14px 的空白，编辑内容最小 40px、行高20px、左右12px。输入与 footer 间距8px，footer按钮28px、左右8px、底部8px。按这些条件静态推算 body98px，实际高度以本轮原生几何验证为准。动态附件、长文本和错误可增加高度，不能固定整个输入框98px。

### 导航轨几何

同版 `499225.6d2e47bea2.js::ld` 使用左右各8px，子按钮 `gdzp→hwkA` 使用36×36及20px图标。因此普通 Electron 轨宽为52px，不沿用旧版本60px。按钮之间8px，顶部按主toolbar高度减36再除2。圆角在不支持corner-shape时为10px，支持时为12.5px及superellipse(1.5)。来源条目与数值位于 layout 中的 `232354.26c2fdfee3.js`、`0040d5ae1a9f.css`，并已核验原包 integrity。导航目的地的门控和用户自定义项另记，不因几何修复假定所有账号固定同一列表。

### 侧栏宽度与整页失败路径

官方同版 `182735.bb2cb0d2af.js::qbQ6` 使用 `sidebar-width`，默认340、最小240、最大520，并按shell宽度减240夹紧。`499225` 的侧栏拖动结束保存。当前实现新增可聚焦separator，原生状态保存后重新读取确认；窗口变窄只夹紧显示，不覆盖偏好。键盘左右10px是等价可访问输入，官方具体步长未证实。未添加缺来源的双击复位。

审查用延迟写入复现折叠重挂竞态：旧350/360写晚于新330，导致磁盘360而可见330。改为同一前端模块共享写队列，重挂读取等待旧队列，回归覆盖重挂后编辑与不编辑。独立窗口并发写入仍未验证。

隔离原生第一次发送失败发现另一确定缺陷：请求已省略cwd/project，但错误页Composer仍展示旧项目及Git分支。修改前回归复现后，使尚无服务端threadId的错误页沿用草稿有效工作区；已有聊天保持原工作区。没有改变请求成功判定，也没有用夹具错误模拟真实模型成功。详细结果见整页验收记录。

错误页仍属于未创建聊天的草稿。选择已有项目及添加目录成功时同样退出显式无项目状态；取消、注册失败和真实已有聊天不改变草稿标记。回归分别覆盖home、thread无ID、thread有ID，避免将路由名字直接当作已创建聊天的证据。

## 2026-11-16 H15 标题项目弹层及焦点合同（修改前）

固定基准不变。新增取证位于`.ref/parity/01/whole-page/reference/focus/report.md`，原包integrity清单与UTF-16锚点随附。标题实际入口tH→uaLq→Rvqv→ZZgR→qhiJ是combobox/listbox，不是旧WorkspacePopover的纯鼠标工作区列表。

- 打开聚焦“搜索项目”。项目行role=option，不进入Tab顺序；键盘高亮与当前项目check分开。上下键不循环，Home/End首尾，Enter选择，IME不执行导航/选择。
- 搜索由外部fuzzy过滤，空结果“未找到项目”；无匹配非空查询直接Enter不得误选footer，须先方向键明确移动。细节可有Git根目录/远端host，不常驻完整path；重名用path tooltip区分。
- footer本地“新建项目”，有当前项目时“不在项目中工作”。远端新建依赖实际能力，不无条件添加。此入口无工作区列表标题、逐行移除或查看AGENTS.md。
- Tab/Shift+Tab在搜索与footer按钮首尾循环。Escape取消返标题trigger；选项目/不在项目中工作后到Composer。外点或焦点已合法转移时不抢焦点。触发器二次点击应正常关闭，不被mousedown外点处理反向重新打开。
- 新建项目先关闭popover，再打开HTML创建表单，初始名称空、sources空。提交createLocal成功后选择返回项目，不能用pick_folder+workspace_add替代创建成功。复用当前真实project/create及表单能力，未支持的外观/默认托管目录等必须登记，不能伪造成功。
- 模型实际为DropdownMenu/Menu。普通menuitem之间Tab/Shift+Tab循环并阻止浏览器默认外移；slider未接管的Tab由底层阻止。不能改成Tab外移后关闭，也不能套项目Popover规则。

当前已复核缺陷为：项目行不可键盘选择、标题按钮二次点击重新打开、模型Tab外移后菜单不关闭且Escape失效。应先补红回归，再按上述合同修复；这份静态合同仍不证明官方当前账号门控、物理IME及像素一致。
