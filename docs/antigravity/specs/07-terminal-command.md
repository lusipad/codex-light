# 07B 终端命令与隐藏恢复合同

日期：2026-11-01，产品修改前建立。

固定原包及资源清单复用 07A reference，新增直接核验 `terminal-panel-295366ae7230.js` 与 `terminal-tab-2c37640cd66b.js`。前者 UTF-16 偏移约 12844 的 onAttach、13121 的 isSessionStarted 与 13686 的 releaseRenderer/条件 close 证明会话启动、附着和渲染资源是独立状态；不是固定毫秒数的就绪信号。该静态片段未证明工具栏命令的完整队列/自动重放策略，以下命令投递合同是本地真实 PTY 必须遵循的数据边界。

| ID | 场景 | 预期 |
|---|---|---|
| TC01 | 终端启动超过 180ms | create_or_attach 成功后才 write，不使用延时推断就绪 |
| TC02 | 等待启动期间隐藏、切标签、卸载 | 原 effect 不继续投递；恢复后未发送命令可以处理 |
| TC03 | 已派发命令后隐藏/重开或重渲染 | 同一 ID 不再次写入；App 清除已处理的 pending，防卸载重放 |
| TC04 | 创建/写入失败 | 显示错误，保留未成功命令，允许显式重试；不自动重复可能执行过的命令 |
| TC05 | 隐藏再打开 | 保留当前进程、标签、输出及高度；隐藏不卸载 terminal DOM |
| TC06 | 关闭最后一个标签 | 后端 close，准备新的唯一 session ID 并选中，重新打开可创建 |
| TC07 | 切项目后运行工具栏命令 | 选择该项目启动目录的标签或新建，不向原项目标签直接发送 |

本轮不实现跨应用重启持久化、完整服务器端输入确认、输出回放去重或所有布局/快捷键。write 失败可能意味着输入部分送达，重试提示必须说明检查终端，不能宣称自动执行安全。
