# 10C 计划任务页面结构纠偏：修改前合同

2026-11-04。依据用户“以当前官方版本取证为准”，不沿旧自建管理卡片反推预期。固定Store26.1027.3384.0，asar SHA-256 `6fbedf054a8d8cafaf5c745b40aa59176512e106e0bd6308275ae123b60fd074`，原文/hash/UTF-16定位保存于`.ref/parity/10/actual/10C-ui-correction/reference/`。

## 来源必须分开

- `/automations`与`/scheduled`并不唯一对应一套UI。runtime Aj经gate3085093835及认证条件选择新ScheduledTasksPage或AutomationsLayoutPage；显式view=manage等条件另有管理入口。当前账号gate未实测，不强开、不假装已知。
- 新ScheduledTasksPage的He读取`/automations?cursor&filter&limit=25`，query key为cloud-automations/scheduled-page；它的自然语言composer需要真实ChatGPT能力。不能把Rust `automations_list`的本地任务冒充该云端列表，也不能做一个假提交框。
- 管理页configuration分支Oo/Ft接收独立localTasks及cloud来源；gate4283773748等决定其与旧建议列表形态的切换。本轮修复当前已有本地功能的**表格管理区域**，不宣布默认云端Scheduled/所有管理分支已完成。

## 区域与动作

| 区域 | 官方静态合同 | 本轮实现边界 |

## 保留不变量

已有`handleCreate/handleToggleStatus/handleDelete/handleRunNow`共享锁、listRequestRef、运行started/finished合并、真实会话跳转、scheduler同步和订阅释放继续有效。运行命令接受只表示启动，completed仅来自真实匹配终态。调度不可用时不派发执行，不显示“回退本地执行”的错误承诺。修改前生产JSX回归已捕获该文字矛盾（退出1）；文字修复后退出0。

不为了换布局重写Rust调度器、存储或协议；不触发模型、真实任务或用户数据变更。现有goal/heartbeat兼容数据和字段保留，但不称它们是云端Scheduled的官方分类。

## 修改前验收

1. 当前本地列表正常/空/失败分别验证；默认已开启，切已暂停/已完成/全部、搜索/排序均不增删数据。
2. 首屏没有实现路径、调度器大卡、代码预设三卡、长期目标分类和全部任务action堆叠；有官方来源的标题、控制栏、列及row入口。
3. 行→详情→编辑/取消/保存/失败保稿，暂停恢复、删除确认取消、运行不可用与重试保持真实行为；原回归不因布局变化弱化。
4. 新增生产TSX回归覆盖实际DOM事件，不能只检查字符串存在；宽窄生产构建检查无横向溢出及可达控件。
5. 配对官方截图、原生GUI/IME、当前gate、云端任务/自然语言composer未实测即明确未验，不给像素分或整页完成结论。

## 10E 关联会话 heartbeat 分钟级执行

[OpenAI Docs](https://learn.chatgpt.com/docs/automations?surface=app) 将分钟级间隔列为会话内定时任务的能力。同一固定官方包的主进程 `.vite/build/early-bootstrap-199-e3316cddb4ea6a6b.js` 在 2116582 附近描述工具入参，528365–532650 附近从关联聊天恢复并发起轮次。`.vite/build/early-bootstrap-339-ce026819bf837ba7.js` 在 409575 附近只为独立任务写执行环境，416900–419960 附近处理 heartbeat 间隔、启动抖动和持久化时间。偏移为 0-based UTF-16。源码定位和 app-server 0.167.0-alpha.3.2 隔离元数据探针见 `.ref/parity/10/actual/10E-heartbeat/` 及上一阶段的 `next-execution-evidence.md`。

| 用例 | 预期 |
| --- | --- |
| 10E01 首次与刷新 | 本地关联任务的简单分钟规则从当前时刻向前安排。刷新与无关字段变更保留同一时点，派发前持久化运行标记。 |
| 10E02 运行与恢复 | 同一任务运行中不重复派发。暂停清除下次运行时间，启用和重启重算，不补跑停机窗口。中断状态未知时自动派发保持阻止。 |

| 10E04 存量与显示 | 官方形状 heartbeat TOML 缺失执行环境时按本地读取。显式环境保留。列表、详情和搜索复用分钟摘要，保留原始 RRULE。 |

适用范围为已有关联会话的本地任务。会话内新建入口、一次性完成状态及官方触发上下文和权限刷新待独立取证。调度扫描仍使用本项目现有 30 秒轮询，长间隔抖动范围对齐官方，哈希算法仍复用本项目实现。

## 10F 新建聊天内的定时任务确认

固定官方 Store 26.1103.4239.0 的 `.vite/build/early-bootstrap-199-e3316cddb4ea6a6b.js` 在 1220290、1232250–1232940 将 `automation_update` 从旧动态工具移到桌面 MCP。1493080–1493560、1513335 显示既有聊天恢复时注入 MCP 配置。2119200–2121560 定义参数，2128640–2130710 将 `destination=thread` 解析为调用所属聊天，2131936 附近在保存前读取持久聊天。官方插件 `.mcp.json` 对该工具设定 `approval_mode: "prompt"`，`server.mjs` 34579–34661 从执行器元数据取得聊天和调用身份。偏移为 0-based UTF-16。

本阶段用 Tauri 已有 app-server 动态工具协议实现同一可观察的创建与确认边界。已验证的 CLI 0.165.0 与 0.167.0-alpha.3.2 允许在新聊天登记并持久化工具。两版公开的 `thread/resume` schema 没有动态工具字段。老聊天的 MCP 接入和官方配对截图待验。

| 用例 | 预期 |
| --- | --- |
| 10F01 入口 | 从普通新本地聊天发送消息时向支持的 app-server 登记工具。普通审查、私有工具连接与不支持的 CLI 保持原入口。 |
| 10F02 用户确认 | 查看任务名称、指令、规则、启用状态，明确选择创建或拒绝。拒绝不写盘。锁屏快捷批准不适用于该任务。 |
| 10F03 身份与回执 | 以连接、请求 nonce 和 app-server 所属聊天为准。确认后验证目标身份和本地持久状态，写入后读回并返回真实任务 ID。模型参数无法指定其他聊天。 |
| 10F04 重复与失败 | 同一聊天、轮次、工具调用标识映射同一任务 ID，已有记录不会被覆盖。无效规则、失效连接、临时或远端会话不创建任务。 |

## 10G 新聊天和冷恢复统一使用桌面 MCP

沿用 10F 的官方 MCP 注册与会话身份锚点。用固定 CLI 0.167.0-alpha.3.2 及本机 0.165.0 通过回环模型夹具验证实际工具流。对照包含同一聊天冷恢复、MCP 模型工具调用、单次确认、工具收到回执。运行时已加载聊天的 `thread/resume` 不采用新增 MCP 配置。直接 `mcpServer/tool/call` 缺少可信轮次元数据。审批策略 `never` 会在 CLI 层拒绝嵌套确认。

| 用例 | 预期 |
| --- | --- |
| 10G01 登记 | 支持的 CLI 新建或冷恢复时加载单次 MCP 配置，不覆盖已有同名配置，不改全局配置。 |
| 10G02 确认 | 子进程仅请求确认，主应用验证本连接 token、真实聊天和活跃轮次，再复用 10F 确认卡。保存及回执均在主应用完成。 |
| 10G03 失败与取消 | 无模型轮次的直接调用、跨会话、过期 token、拒绝及取消均不创建；工具取消会撤回内层确认。 |
| 10G04 兼容 | 已加载且此前未登记的聊天，冷恢复后才能使用。原先已持久登记的动态工具请求仍能通过旧处理链。 |
