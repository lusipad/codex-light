# 06D 变更列表的文件路径

沿用 [06C 基准](06C-split-alignment.md)。官方 `.vite/build/worker.js` 1138861 附近使用 `git status --porcelain=v1 -z` 读取原始路径，并在重命名或复制记录后消费附加路径。位置为从零开始的 UTF-16 偏移。

当前文本模式把 Git 的引号和转义直接当作文件名，导致列表乱码和单文件差异为空。沿用机器可读状态输出，保留重命名目标名称，并将单文件路径按字面传给 Git。验收覆盖中文、空格、方括号、重命名后相邻记录，以及差异和索引动作只处理选中的文件。

## 回归

- 两个真实 Git 用例先因路径不匹配失败。修正后完整 Rust 套件 715 项通过，前端 114 项回放、Git 生命周期及发布元数据检查通过。
- 路径测试同时保留两个容易被 Git 通配符混淆的文件，确认差异只含目标正文、暂存只写目标、取消暂存清空对应索引，以及放弃时相邻文件字节不变。重命名测试验证目标名和下一条记录，重命名前后路径的成对操作留待单独核对。
- Windows EXE、MSI、NSIS 构建通过。原生变更列表显示中文、方括号和 emoji，分别选中 `中文 [1].txt` 和 `中文 1.txt` 后读取各自的补丁。工作区文件哈希一致，索引为空。EXE SHA-256 为 `f1794f9aa54ff3a88db90099cebf7712b01930a6af586b6fd42613a9a06c9506`，记录位于 `.ref/parity/06/actual/06D-git-paths/native/verification.json`。
- 补丁正文保留 Git 原始引号规则，因此原始补丁头在 `core.quotePath=true` 时仍可能显示八进制转义。官方同环境像素和用户验收待完成。
