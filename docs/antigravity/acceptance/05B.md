# 05B 保存前内容检查与写后回读

日期：2026-11-03。限定范围本地功能自验及构建归档完成，原生/官方配对与整页验收未完成。

依据：[外部变更与关闭合同](../specs/05-file-conflicts.md)。本轮优先修复其指出的无条件覆盖风险；暂不接入关闭自动保存或新增冲突弹窗。

## 范围与预期

1. 保存前通过真实`fs/readFile`读取当前磁盘内容。磁盘与当前编辑基线不同且不等于提交快照时，不写入，不清草稿或dirty。
2. 磁盘已经等于提交内容时，可以收敛成功而不重复写入，用于恢复前次写入已生效但确认失败的情况。
3. 写入后再次读取，只有读取内容等于提交快照才更新基线；保存期间的后续编辑仍保留dirty。UTF-8 BOM和CRLF保留，无效UTF-8拒绝保存。
4. 预检期间换文件、关闭、卸载或工作区变化时，不启动过期写入；失败不进入另一个写入后端。
5. 协议读取或写入不可用时，保留草稿并报告失败。本轮主动取消编辑保存的通用`fs_write_file`回退：写入失败可能已经生效，再次回退会绕过检查。创建新文件的既有路径未变。

这只是**非原子的内容预检与回读**。预检与写入之间仍可能有外部写入；回读也无法阻止随后变化。不宣称跨进程CAS、mtime保护或官方完整冲突review已经实现。

## 实现与验证

- `src/fileEditorSave.ts`：生产保存函数，复用已有fs协议封装，无新依赖。
- `src/components/DiffDrawer.tsx`：复用单次在途保存、文件请求身份、编辑版本和现有toast；冲突不更新保存基线，过期错误不提示当前文件。
- `scripts/verify-file-editor-save.mjs`：执行生产函数，覆盖前置冲突、已落盘收敛、失效、读写/回读失败、不回退、回读冲突、无效UTF-8，以及隔离临时目录中的真实BOM/CRLF文件往返。IO替身不能证明真实app-server或Tauri调用已通过。
- `scripts/verify-file-editor-lifecycle.mjs`：原有FE01–FE06运行真实组件回调，保存设施为受控替身。保存函数另测，不能将两者描述为完整原生端到端。
- `scripts/verify-all.ps1`纳入新回归。最终命令与构建身份见[验证记录](../../../.ref/parity/05/actual/05B/verification.md)。
- 完整标准检查、Tauri EXE/MSI/NSIS构建及diff-check均退出0，190项产品输入保持一致。[可运行EXE](../../../dist-artifacts/05B-file-save-20261103/CodexNative.exe)及[产物清单](../../../.ref/parity/05/actual/05B/build-manifest.json)已归档。本轮未修改Rust源码，未额外重复23G的213项库全测，Rust覆盖为标准脚本中的检查与过滤测试。
