## 实现范围

- 复用目录分页 loader、Composer、现有桥与桌面 JSON 存储；共同能力解析区分目录 ID 和请求 model、普通列表与显式配置的隐藏模型、真实推理档、真实速度层 ID 及账户准入。不能把存在 fast 目录项当账户授权，未知 gate 不强开 ultra。
- 模型变更保留仍受支持的 effort，失效再使用模型真实默认。菜单、快捷键和发送共用同一三元组。默认目录速度层与显式标准区分，标准持久化为协议已验证支持的 `service_tier:"default"`；恢复时归逻辑 null。
- 新草稿、持久默认、当前会话分别处理。默认用户层三键写携版本 CAS 并读回；当前会话走 `thread/settings/update`，处理 pending、失败、多个会话并发写与迟到恢复。旧版 profile 不受当前 CLI 支持，明确拒绝写，不能悄悄覆盖根默认。
- `thread/read` 恢复模型及 effort；`thread/resume` 进一步取得速度配置，未取得则显示限制并允许明确重选。服务 `thread/settings/updated` 是实际配置更新来源，跨窗口和归一化结果不被本地请求值覆盖。
- 普通发送、目标首轮、Plan、重发、Quick Review 和队列启动使用共同校验结果。队列先确认下一轮设置再启动；steer 使用正在运行轮次的上下文，不注入协议不支持的模型参数。Plan 设置失败保留输入并不启动未确认配置的轮次。
- `/model` 和 Windows `Alt+M` 打开独立最近模型子菜单，历史＋当前＋目录过滤去重最多三项；有搜索及匹配分区。菜单点击不记最近使用，仅本 UI 真实提交并匹配 `item/completed:userMessage` 的 thread/turn 记录，早于 RPC 回应的事件先缓存。助手随后失败不撤销已确认使用。Quick Review、非 UI 来源与没有可靠执行身份的失败请求不冒充普通使用。
