# 08S 聊天搜索排序与选择自验

按[开发前规格](../specs/08S-chat-search-ranking.md)，独立聊天搜索按 ID 合并已加载聊天和协议页。标题、正文、分支、项目和目录按字段优先级排在同一列表，再应用条数上限。重复项保留已加载名称与首个有效正文片段。同字段按活动时间排序。

- 生产回放验证 26 条协议结果也无法挤掉更高优先级的标题。覆盖重复元数据、片段保留、查询范围隔离、分页后的首个新增项、选中项离开当前页时 Enter 无动作。
- 隔离原生窗口输入 `repair-ui`，协议夹具延迟响应期间按方向键选中仅分支命中的「构建结果」。释放正文响应后，宽窗和窄窗显示标题、正文、分支的顺序，「构建结果」从第二行移到第三行仍保持选中。Enter 后 `thread/read` 与 `thread/resume` 都指向原选中 ID。无模型请求，测试窗口已退出。
- 125 项发布前端回放、TypeScript、Store 自带 CLI 的隔离搜索探针及 Windows EXE、MSI、NSIS 构建通过。最终 EXE SHA-256 为 `0883f6794a990f59c3643e8de32b8f51b938357b5cc73007e283b76bccbf79ed`。截图、协议日志和构建日志位于 `.ref/parity/08/actual/08S-chat-search-ranking/`。

仍用现有字面匹配，官方同字段模糊评分、非连续高亮、多宿主与同环境像素待验。本轮未重跑完整 Rust 单测。
