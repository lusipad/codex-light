# 16.01C 工作区动态打开方式与执行前目录确认

2026-11-03。限定功能增量自验完成，待用户验收；通用设置、整16页及整个App均未验收。

## 来源与实施

[修改前合同](../specs/16-01-next-closure.md)分别保留旧离线候选5文件和Store 26.1021.3705.0的9文件证据，不混用版本。Store签名/BlockMap来源见[核验记录](../../research/reference-store-20261103.md)。静态链证明动态getTargets/open、精确perPath优先、显式选择执行前保存，以及新版本点击前查询会话最新工作树根；不能据此宣称官方运行时已测。

- `src/workspaceOpenTargets.ts`、`App.tsx`：打开菜单实时查询，过滤隐藏/不可用目标，展示偏好、加载和错误状态。空目录不造目标；显式选择调用真实宿主命令，隔离关闭/切会话/卸载后的晚到结果，防重复提交。撤下未注册的open_in_vscode和用内嵌终端冒充外部打开的菜单项。
- `ThreadActionsMenu.tsx`：复用现有菜单，动态内容重新定位，异步加载完成后保留键盘焦点意图；打开状态卸载通知查询失效。
- `desktop_open_context.rs`、`lib.rs`：查询和执行各自重新thread/read，校验ID、local环境和同会话applied根；不使用pending、不在会话查询失败时退回侧栏旧cwd。必要时用同Git仓库精确owner metadata定位工作树，歧义报错。
- `desktop_open.rs`：复用现有目标检测和偏好存储，精确路径优先于global，清理未知目标并兼容finder迁移。显式目标必须有效；写偏好失败不执行，执行失败不伪报成功，已写偏好不擅自回滚。
- Windows VS Code类目标使用实际存在的cli.js及ELECTRON_RUN_AS_NODE，兼容直接和唯一版本子目录，检查退出码，30秒超时报告未确认。其他GUI/Explorer通过ShellExecuteW，仅证明系统接受请求。

没有新依赖、没有新增假想后端协议或第二套菜单引擎。既有通用外部打开接口保持兼容。

## 受控浏览器与待验项目

真实hook与菜单生产组件夹具验证了：首次查询失败显示禁用错误项；Escape返回触发器；重开查询成功；选择文件资源管理器仅一次请求并关闭菜单、焦点返回；重开选中态读回为文件资源管理器。保留workspace-open-browser.png、AX及browser-verification.md。目录/打开结果均注入，没有启动真实编辑器或保存用户偏好，不是原生或官方像素验收。

在隔离原生环境应继续验：真实目标检测→会话根变化→点击显式目标→应用启动与实际目录→重启偏好读回→不可用/失败→键盘/焦点/IME，并与固定官方环境配对截图。Windows/DPI/App缩放尚未固定，当前没有可用的同环境配对图，视觉评分未执行。

剩余边界：完整目标目录、外部Terminal、remote/location/custom handlers未完成；ShellExecute接受请求不等于GUI就绪，也不完全等价于官方close判定。没有Store独立workspaceRoot服务，已删除cwd无法据此找回其他仓库；其他工作树metadata未知/损坏会保守阻断。Git根查询没有单独deadline，CLI启动器30秒限制不覆盖该链，尚未实测其挂起。notLoaded且environments:null为真实支持的形状，无需伪造resume。
