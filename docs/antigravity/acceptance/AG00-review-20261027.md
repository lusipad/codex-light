## 3. 必须修正的问题

### R1 / P1：结构测试仍在充当像素验收，且可接受明显错误

位置：`scripts/verify-unit-01a-shell.mjs:19–32`；`acceptance/01A.md:37–40`；本run `diff/anchors.csv:2–4`。

脚本只是检查变量字符串、排除固定36px/align-self:center等写法。隔离反证把 `.app-window-controls` 从 `height:100%` 改成 `height:1px` 后，脚本仍输出：

```text
PASS DIFF-01A-02: Window controls full-bleed 54px flush against top
ALL 01A PUBLIC SHELL PARITY CHECKS PASSED!
exitCode: 0
```

因此，这一脚本不能证明实际控件高度、贴顶、拖拽、菜单、焦点或像素差。锚点表引用该脚本与CSS行号填actual=reference和dx/dy=0，没有测量来源。

**返工要求**：保留脚本为结构检查并修正文案；撤销无依据的像素通过结论。提供当前EXE的同尺寸截图、控件边界测量和对照图，或保持未验证。行为测试要实际执行动作；1px反证必须被真正的几何测试发现。

### R2 / P1：宣称已物理采样的颜色与被引用原图不吻合

位置：本run `baseline.json:34–38`；`acceptance/01A.md:27`；规格控件表及DIFF-01A-04。

官方首页原图SHA与清单一致，本次直接读原始像素：

| 原图坐标 | 实际像素 | 文档对应声明 |
|---|---|---|
| (500,20)、(500,40) | `#1A2129` | 标题栏实测 `#1A2229` |
| (25,300) | `#1C2124` | 导航轨实测 `#1B2026` |
| (30,500) | `#212020` | 同上 |
| (30,650) | `#202021` | 同上 |

不同点可能包含状态、背景变化或其他采集因素，**不能直接把其中一个取样值指定为新的CSS token**。能确定的是交付没有给出支撑其统一色值的采样点、ROI、状态或实际CSS选择器来源，却已将这些值写入产品并称“官方一致”。

**返工要求**：保存可重跑的采样方法、坐标/ROI、原图哈希和变体；关联官方实际使用的token/选择器，区分像素观察与样式定义。冲突未消歧前基准值标待核实，不继续据此调整更多UI。

旧actual中的 `native-home-after.png` 实际是JPEG签名，且旧图不能证明新EXE。交付自己的claim-audit已正确指出旧图格式/尺寸问题，本轮却没有补新证据。

**返工要求**：同一源码构建的新实际图、同条件官方参考、测量/差图、原生动作及焦点记录齐备后再填G5–G7。缺少S02、S11和窄窗时保持相关用例阻塞，不能直接声明当前材料“完全满足01A验收前置要求”。

### R4 / P1：动作合同仍在使用未经取证的通用实现假设

位置：`specs/01-home-shell.md:97–130` 和控件清单。

例子：A03写“关闭退出/隐藏”未确定实际语义；A05断言localStorage持久化但无官方动作证据；A10写“内存或本地持久化”无法形成唯一可验收结果；A17写“当前项或首项”未消歧。动作表没有逐行官方证据ID与观察步骤。默认截图也无法证明hover、焦点、关闭后位置或持久化。

控件表还把单张默认图作为role/ARIA、hover色、disabled透明度等动态/非图像信息的来源，没有给对应UIA/DOM/语言包/适用CSS锚点。例如“搜索条/searchbox”与截图中的搜索入口需要重新对应，不能按常见产品结构补充。

**返工要求**：每项明确哪些是官方观察、静态分支、当前实现或未知。没有证据就填未知和采集步骤，不给出“合理默认”。先补齐01A所需的A02/A03/A05/A06/A07合同，其余先登记。
