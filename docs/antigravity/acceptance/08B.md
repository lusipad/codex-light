## 实现与对应行为

| 场景 | 本轮实现与证据 |
|---|---|
| root搜索文件 | 仅展示可筛选的“搜索文件”入口，不请求或混入fuzzy文件命中；进入files清空query并保持输入焦点 |
| root聊天 | 2字起匹配已加载聊天；3字起200ms防抖发真实thread/search，最多9条；本轮未增加chats模式/多host |
| 线程缓存 | 包括失败catch空值在内的30秒stale缓存；不再组件全生命周期永久有效。附加cwd为本项目隔离策略，并非官方请求参数 |
| files非空query | 任意非空长度使用真实sessionStart/Update通知链，先订阅再启动；不加共享150ms防抖或query缓存 |
| 查询更新 | 启动期间仅投递最新query；已发旧update的慢应答不扣住新query；通知按sessionId及query过滤 |
| 关闭、换模式、换工作区 | 失效回调和订阅；session创建/重建落定后stop，不等待普通update应答；晚到结果不回写 |
| 兼容与重连 | 只有明确method unsupported才用单次fuzzyFileSearch；session-not-found重建并补update；权限等其他错误不伪装成兼容成功 |
| 文件结果 | 保留真实Unicode文件名及路径、文件去重与官方排除目录；不再用旧workspace目录列表补出已删除文件 |
| 空files | 不发搜索请求；显示输入提示。真实“最近打开”数据源尚未实现，不把目录列表冒充最近文件 |

复用既有app-server桥、App模式状态、QuickSearch组件与样式，无新依赖、无Rust产品改动。
