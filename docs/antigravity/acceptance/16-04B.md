## 固定来源与本阶段改动

独立使用 Store `26.1027.3384.0` 作为本单元静态候选来源，原包 SHA-256、签名、10289 个 BlockMap 块及提取文件已核验。旧页面继续保留自己的固定来源；本轮不自动升级整个项目的视觉基准。中文、通知消费者、宿主服务、物理存储与声音采样率均先补证再开发，精确来源见上述四份合同。

- 原生链复用既有 `notification_broker` 的全窗口焦点、可见会话和去重仲裁，不另建一套 owner 选举。真实事件携稳定业务 ID、账号 epoch、host/thread/request 身份进入宿主，使用 Tag/Group 登记、Activated/Dismissed/Failed 生命周期及精确撤回，解决/已读的 tombstone 阻止晚到旧提醒。同会话较新提醒不被旧时间边界误撤回。
- Windows 适配使用本机 MSVC 和 Windows SDK C++/WinRT，经限定 JSON C ABI 接 Rust；没有新增 Cargo/npm 依赖，不复制官方 Electron 代码。`Show` 结果称 `submitted`，不伪称已在屏幕展示；原生通知 silent，声音由同一真实播放器承担。权限读取真实 `ToastNotifier.Setting`，不采用插件恒 Granted；仅用户点击打开固定 `ms-settings:notifications`。
- App 收到正文点击只导航并定位当前请求；仅明确审批动作才进入真实回复，执行前重新核账号、generation、待处理请求及当前支持的决定。宿主给每次请求登记生成独立 notificationNonce，通知ID与payload携带该实例；实际响应在宿主锁内再次核验，避免同连接复用ID时旧通知批准新请求。已经解决、旧账号或未知动作不执行审批。菜单 payload 的 reply 字段尚未在 App 真实新 turn 消费链接通，不能把接口字段存在当回复功能完成。
- 五项偏好改用真实用户层 `desktop.notifications-*` 配置、版本化写入和读回；缺键时读取旧值，不自动批量迁移或清理旧文件，保留显式 false/off/none、自定义对象和无关字段。确认失败返回 false，界面不先选中新声音；跨窗重新读取有效配置，不传播未经确认的值。沿用现有协议、组件样式和存储模式。
- 设置页真实查询权限并在窗口 focus 后刷新，最新查询胜出；disabled 锁相应控件，unknown 明示未知而不伪造开启。系统入口只在 disabled/not-determined 显示。官方中文四类设置、自定义声音菜单、取消无保存、失败反馈、选择后单次试听及导入后焦点返回已接通；撤下无官方依据的测试通知和单独试听按钮。
- 导入使用固定 **48000Hz OfflineAudioContext** 真实 `decodeAudioData`，校验 mono/stereo、非空、严格小于30秒，转交错 signed16 PCM；宿主复验并构造 RIFF/WAVE，按内容 SHA-256 命名，临时文件写入/rename 后逐字节读回。只保存 `{fileName,name}`，不依赖原文件路径。试听、真实通知和 none 共用 Windows 文件播放器，离页/新选择使旧导入和试听失效。
- **未复制、打包或分发官方音频。** 默认/经典仅从本机固定 Store 资源读取并核哈希，版本移除、资源不可读或变化时真实失败；自定义音使用用户自行导入的文件。资源许可和独立安装后的内置音可用性仍未解决，不宣称音色已达1:1。

## 用户验收步骤（待最终构建，尚未执行）

1. 使用本阶段最终同源码安装构建和隔离CODEX_HOME；记录Windows版本、官方固定版本、主题/语言、DPI、App缩放及客户区尺寸。确认首次打开设置读取实际权限，未知不冒称已开启；仅用户点击打开Windows设置，返回/聚焦后刷新。
2. 实际改变turn off/unfocused/always、权限/提问/Dot开关，离页重开、重启读回；用第二窗口和外部版本变更制造冲突，确认不覆写无关值、失败不假报保存。Dot只验开关，不制造本地Dot消息。
3. 在隔离真实工作区产生合法完成/权限/问题事件，检查前台/后台与可见会话矩阵、多窗口只一次；quiet/取消不伪报成功。分别点击活动banner正文和进入Action Center后的条目，确认只恢复一个正确正常窗口并定位正确会话/请求，正文不得提交审批。
4. 对真实仍待处理请求点击明确允许/本次会话允许/拒绝，核对实际后端决定；重复、解决后、账号切换后及导航途中身份变化不能重复或越权提交。回复输入目前未接通，不将此步骤的通知正文定位当作回复通过。
5. 通知显示后解决/取消请求，或打开会话标已读；在OS中心确认精确移除旧条目、保留别会话与较新通知。逐项记录失败、close、TimedOut与替换；submitted不能代替截图或事件证据。
6. 导入有效MP3/WAV/FLAC/Ogg，验证真实解码、保存读回与只试听一次；原生取消、空/损坏、>10MiB、恰30秒、多声道、中文/空格/引号长路径逐项检查。删除原文件后重启仍播副本，删除/篡改副本显示真实失败；验证none仍允许通知但不发声。
7. 连续切音、解码中离页、双窗替换和关闭源窗，确认旧音停止、晚到结果不保存。默认/经典仅本机固定资源可用时测实际音频，缺资源明确失败，不以合成音或别的系统音替代。
8. 检查最小化/关闭源窗、仅剩Quick Chat、全退出后中心点击、重启与安装/卸载标识清理；当前缺口按下面清单记录，不能绕过后标通过。同条件官方/Tauri宽窄原生截图、AX、几何/叠加差异另行采集，缺官方基准不打像素分数。

## 剩余缺口与未验项

- Windows通知中心真实点击/动作/撤回、实际审批执行、实际音响与格式编解码器、双窗/最小化均未验。SDK单测和生产组件夹具只覆盖限定逻辑。
- 应用退出后的COM冷启动激活尚未完成；仅剩Quick Chat时宿主尚不能创建正常导航窗。安装/卸载通知身份清理未完成，重启后conversation时间索引不持久，不能恢复旧进程所有业务元数据。
- App没有接通通知文本reply启动真实turn；XML/载荷字段存在不等于回复可用。Windows OS输入框/按钮表现也未实测。
- 当前明确审批按钮会先导航到对应聊天再核验/回复；官方静态动作回调直接回复而不返回导航。此行为差异仍待纠正及原生验证，不将后台审批的界面副作用记为严格一致。
- Dot目前仅保存/展示开关，无真实Dot服务事件源；当前Dot抑制矩阵尚未全部按新候选的相同可见会话规则更新。远程ChatGPT账户通知服务未接入。
- 固定Store默认音依赖及分发许可未解决，不保证离开开发机器后内置音可用。不得将本机资源只读播放称为已分发官方音资源。
- 官方运行时、原生像素、完整通知分区和用户验收仍未完成；阶段构建/提交不能代替验收。
