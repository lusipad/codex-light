修改产品源码前，新增 `node scripts/verify-project-index-sort.mjs` 执行整个生产 `ProjectsIndexView`。PS01 实际 `[a,b,c,d]`（原持久顺序），预期 `[b,c,a,d]`（有效更新时间降序），退出1。排除异步加载未结束导致的空列表后保留该真实行为红灯。

最小实现后该命令退出0，覆盖：

| 用例 | 结果与证据范围 |
|---|---|
| PS01 | 初始有效更新时间降序，项目时间与所属聊天时间取最大；时间平局按名称/ID，并随整列降序翻转 |
| PS02 | 混合项目秒/毫秒显示同为1小时前；聊天秒时间显示1分钟前，显示与排序一致 |
| PS03 | 名称首次升序，再点降序；大小写不敏感平局以 ID 打破 |
| PS04 | 搜索只过滤，不改变当前方向或数据集合 |
| PS05 | 换回更新时间默认降序，再点升序 |
| PS06 | 展开后重排仍以同一项目 ID 保持展开，不依赖索引 |
| PS07 | 保持同一 sort，单独替换 threads 数组；再经 project/changed → 生产 loadProjects → 新项目列表更新。Object.is 缓存尊重 memo 依赖，验证聊天毫秒值不重复放大及数据变更后排序/显示重新计算 |
| PS08 | 原 projects 数组顺序不变；无创建/移动/更新/删除持久写入，无新聊天或选择聊天副作用；表头使用原生 button |

原回归 `node scripts/verify-project-index.mjs`、`node scripts/verify-organization-ui.mjs` 以及 `npx tsc --noEmit` 均退出0。旧回归继续覆盖同根项目身份/全部根、新建失败重试、迟到加载、IME/忙碌表单与原项目操作菜单派发。`git diff --check` 无空白错误（Git 提示 CSS 将按仓库规则使用 CRLF）。
