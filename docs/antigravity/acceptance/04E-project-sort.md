## 红绿证据

修改产品源码前，新增 `node scripts/verify-project-index-sort.mjs` 执行整个生产 `ProjectsIndexView`。PS01 实际 `[a,b,c,d]`（原持久顺序），预期 `[b,c,a,d]`（有效更新时间降序），退出1。排除异步加载未结束导致的空列表后保留该真实行为红灯。

最小实现后该命令退出0，覆盖：

| 用例 | 结果与证据范围 |
|---|---|
| PS01 | 初始有效更新时间降序，项目时间与所属聊天时间取最大；时间平局按名称/ID，并随整列降序翻转 |
| PS02 | 混合项目秒/毫秒显示同为1小时前；聊天秒时间显示1分钟前，显示与排序一致 |

| PS04 | 搜索只过滤，不改变当前方向或数据集合 |
| PS05 | 换回更新时间默认降序，再点升序 |
| PS06 | 展开后重排仍以同一项目 ID 保持展开，不依赖索引 |
| PS07 | 保持同一 sort，单独替换 threads 数组；再经 project/changed → 生产 loadProjects → 新项目列表更新。Object.is 缓存尊重 memo 依赖，验证聊天毫秒值不重复放大及数据变更后排序/显示重新计算 |
| PS08 | 原 projects 数组顺序不变；无创建/移动/更新/删除持久写入，无新聊天或选择聊天副作用；表头使用原生 button |
| PS09 | 生产按钮无新增 title；方向图标使用官方已证150ms和 cubic-bezier(.4,0,.2,1) |

复审同时纠正测试 harness：原 useMemo 总重算、原地修改 fixture 和同时切换排序的样本会掩盖漏依赖。现按 Object.is 缓存 useMemo/useCallback，数据变更保持 sort 不变，通过新数组/生产通知链触发，未修改产品依赖数组（原依赖已完整）。

## 主线程浏览器与复审

独立复审已核对官方整列方向和平局比较器；旧真实project/list样本有秒时间戳，Thread schema同为秒，毫秒分支作为既有兼容路径验证。移除原文没有的title，动画采用同版CSS的150ms及cubic-bezier(0.4,0,0.2,1)。最终PS01–PS09尊重Object.is memo缓存，项目更新经真实project/changed监听→loadProjects→新数组读回，聊天更新保持排序状态不变，修复了初版测试总重算掩盖依赖的问题。

`.ref/parity/04/actual/04E-project-sort/browser/`使用当前生产组件和真实React、内存桥、CSP禁外网。1280×800与640×800实测：默认Beta/Gamma/Alpha，Enter名称升序、Space降序且焦点仍在按钮；筛选清除保留方向；不切排序时更新聊天props，Alpha移到首位且Beta展开状态保留；窄窗时间按钮/单元隐藏，Tab/Enter/Space名称排序可用。两尺寸document无横向溢出；无额外title，实际动画曲线吻合。它不是实际项目服务或模型证据。

宽窗实测根字号13px、列772/52/104px，部分“31 分钟前”时间文案占两行。官方只证明4rem/8rem，尚无官方运行时根字号测量，不能把默认16px设计假设当成64/128px事实。本轮保留并登记该呈现差异，不未经证明扩大布局修复。原始JPEG、几何与结果在同目录；score=null，整页像素及用户验收未通过。
