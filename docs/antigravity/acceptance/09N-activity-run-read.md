# 09N 活动页定时任务已读验收

按[开发前规格](../specs/09N-activity-run-read.md)接入调度器的未读运行集合。优先事项、活动入口提示、未读圆点和批量动作使用真实回执。普通聊天仍使用 app-server 修订号，活动行打开和批量操作使用 09M 的运行写入边界。

## 原生验证

使用当前 EXE 与隔离 Codex CLI 0.165.0。夹具包含 12 条离线聊天，其中两条为预置已完成任务运行。任务暂停，普通聊天回执实际经过本地 CLI。验证中模型用量为 0。

- 默认隐藏任务聊天。开启筛选后，两条普通聊天已读但运行未读的记录进入优先事项。最终构建中两行均显示蓝色圆点及「未读消息」可访问节点。
- 注入临时文件写入故障，原生窗口保留两个圆点并显示拒绝访问。状态文件哈希不变。解除故障再打开第一条，只有第一条写入运行回执。
- 首轮批量动作同时清除了另一条运行与九条普通聊天的未读。最终构建再验证仅剩运行未读时，批量动作仍可写入。重启后两条回执保持原值，任务聊天回到「今天」，活动提示熄灭。
