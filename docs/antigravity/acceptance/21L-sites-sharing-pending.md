# 21L Sites 分享邀请状态

邀请返回 `pending` 后，弹窗用实际选择的身份显示「待处理」。已读权限与临时参与者行分开保存。查找候选和提交时排除相同身份，其他对象仍可依次邀请。重开时读取权限，已返回的记录使用服务字段。

- 官方固定版本的 `h` 原函数隔离回放 10 组通过，覆盖成员、邮箱、团队、角色和失效权限分支。原始定位和动作矩阵见[21L 规格](../specs/21L-sites-sharing-pending.md)。
- 实际弹窗及状态 39 组、搜索控制器 8 组通过。包含 ACK 晚到、撤权、不同对象连续提交及重复目标拒绝。被拒绝和未知结果仍走已有错误与读回流程。
- 浏览器以实际页面和本地隔离桥验证键盘选择、待处理行、重复搜索和重开读回。记录为 1 次写入、GET 从 1 次变为 2 次、重开后待处理行变为服务邮箱行。1280×800 和 440×800 下状态行可见，无横向溢出，控制台零错误。证据见 `.ref/parity/21/actual/21L-sites-sharing-presentation/browser/`。
- 本地 CI 前端命令的 93 项回放、完整标准检查的 347 个步骤（含 32 个协议探针）及 Windows debug 构建均成功。原生候选包通过启动、未登录站点路由和退出检查，构建的 710 个输入前后哈希稳定。EXE 位于 `dist-artifacts/sites-21L-20261107/CodexNative.exe`，SHA-256 `9e05c6d506d5f27acc8d4274da68a15f74091a023e93f0c1fa330876c7cb2755`。
