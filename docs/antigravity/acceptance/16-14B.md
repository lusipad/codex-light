## 实现与复用

- 设置从单一活动目录原始 TOML 编辑改为全部已登记项目索引→环境详情→结构化编辑。保留项目路径身份、继承分组、损坏配置、默认及三平台 setup/cleanup、动态 actions；新增文件递增命名，不覆盖原有文件。
- `local_environment.rs` 沿真实 Git 边界最多 50 层发现，精确校验配置路径、原文版本冲突、落盘读回。保存与选中分两步；选择使用宿主/规范化根键，区分未选择、明确无环境与读取失败，失败不悄悄默认或重写。保留旧 read/save/action API。
- App 两条新 worktree 发送/目标路径及 WorktreesView 共用真实创建 client，宿主统一读取实际选择。setup 使用当前平台非空脚本或 default，映射配置及子项目目录，写 worktree 作用域选择，等待真实 shell 退出。
- 新 `local_environment_setup.rs` 复用 Git 创建及已有 Windows Job：先挂进程树再恢复执行，成功/失败/取消都清理管道持有者。注入真实源/目标工作区变量；成功环境差量保存至 worktree Git-dir，`terminal.rs` 新 PTY 实际应用 set/unset。
- UI 不把排入终端等同命令完成；setup 失败/取消返回真实已创建目录并保留，不自动删除、不自动重试、不继续 thread/turn。同步登记 prepared operation 后再后台排队，窗口销毁可取消排队工作；重开同标签窗口不会复活旧 token。
- 原生窗口、账号/连接、路由、工作区、同根项目或附加根变化、新草稿均使旧创建取消；失败后工作树列表刷新且错误保留。设置 dirty 原生 dialog、Escape 焦点返回、保存冲突保稿、选择重试不重写文件。
- 复用现有主题、图标、Git、文件冲突与原生进程能力，无新依赖。仅暴露已有 Job 的必要 crate 内可见性，没有复制 Windows FFI 或新建执行框架。

## 适配限制与待验

- cleanup 当前仅可编辑/保存，尚未接工作树删除或自动清理；动作目前从设置页检查并发往真实终端，顶部栏菜单、官方专用动作会话重启链仍待接。当前排队不代表专用动作进程退出成功。页面如实说明，不沿用会误导已实现的官方描述。
- Windows runner 支持实际 PowerShell/pwsh、cmd；其他 Windows shell 明确拒绝，不声称全部 shell 等价。Unix 分支尚未在 Linux/macOS 运行。实时逐条输出 UI、官方完整 setupResult/日志呈现仍待对照；当前可核真实退出及 Git-dir 日志。
- setup 成功环境目前用于新建的本地 PTY，未证明 app-server 模型工具、既有终端及远程宿主都自动继承。setup 自身可以有任意真实副作用，取消不等于回滚；已创建工作树保留，重试需用户明确操作。
- 读取/最终 rename 与外部 Git/文件写之间没有跨进程事务。结构化 TOML 保留脚本文本，排版不承诺官方字节等价；当前旧严格 schema 读入空名称等边界与官方宽松解析仍有差异，未自动迁移损坏文件。
- 固定 Store 远程 gate 分流、SSH/host、cleanup/自动化消费者仍未通过。只使用真实已登记根，不扫描磁盘中所有项目。
- 最终 Tauri GUI、真实用户环境、IME、官方同客户区/DPI/主题/语言宽窄图、逐物理像素及用户验收未完成。没有匹配官方参考图，不填虚构 visual-verdict 分数。
