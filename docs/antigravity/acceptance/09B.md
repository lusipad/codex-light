## 实现与范围

开始开发时，侧栏已经使用23D的真实未读会话数。本轮修复等待审批/用户输入未读点缺失：

| 状态 | Activity列表候选 | 需要注意提示 |
|---|---|---|
| 有有效未读receipt | 是 | 是 |
| waitingOnApproval / waitingOnUserInput（status或activeFlags） | 是 | 是 |
| active / running，已读且无waiting | 是 | 否 |
| idle、已读或无receipt，且无waiting | 否 | 否 |
| 只有旧本地未读通知 | 不据此加入 | 不据此点亮 |

`src/threadActivity.ts`的两个判定被App列表候选和提示计数复用；
Sidebar使用同一候选ID集合，不再维护第二份status/flags判断。
`activityAttentionCount`明确与NavigationRail独立Inbox计数区分。
补充已有`ThreadSummary.status.activeFlags`类型，无新依赖、无Rust产品变更。

已有全部已读handler继续使用真实`thread/readState/update`、expectedRevision、
逐thread互斥及完成/失败后的权威刷新。没有新增乐观清空通知或成功toast。
等待审批不能通过“全部已读”消失：提示仍取waiting状态，直到真实状态变化。
