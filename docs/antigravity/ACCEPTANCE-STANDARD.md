# 界面、动作、呈现效果与验收标准

用于每个页面、菜单、弹窗、设置分区、原生窗口。配合 [任务模板](TEMPLATES.md) 填写实际规格。

## 1. 必须独立记录的结论

每个用例分别填下列字段，禁止一个 PASS 复制到全部列：

| 维度 | 它实际证明什么 | 单独不能证明什么 |
|---|---|---|
| 官方预期证据 | 固定版本在指定条件下应呈现/执行什么 | 其他版本、账号、模式也相同 |
| 结构检查 | 某路由/字段/调用/样式定义存在 | 分支执行、真实 UI、数据写入、像素 |
| handler/回放 | 实际函数在给定输入下的结果 | 浏览器事件链、真实服务、物理键盘/IME |
| 组件/浏览器行为 | 用户动作、DOM/焦点与请求链路 | Tauri 原生权限、窗口、真实服务一定正确 |
| 真实服务与读回 | 当前能力下的真实数据与协议往返 | 官方界面一致、所有故障和账号均通过 |
| 原生同构建操作 | 对应 EXE 的真实 UI/系统交互 | 官方同条件也如此 |
| 视觉对照 | 对应状态与条件的几何/像素差异 | 点击逻辑、持久化和真实服务 |
| 用户验收 | 用户明确接受的单元/场景/限制 | 未覆盖范围全部完成 |

结果枚举：通过、失败、未执行、外部依赖阻塞、不适用。后两项必须写依据；不可默认为通过。固定样本不是坏测试，但必须标注它只验证客户端处理。

## 2. 环境固定与参考图可信度

采集双方记录：

1. 官方版本/build、安装包和相关资源 SHA-256；本项目 HEAD、未提交补丁及新文件哈希、EXE 哈希。
2. OS、屏幕 DPI/缩放、应用缩放、WebView/Electron、字体和 fallback。
3. 产品模式、语言、主题、账号能力摘要、可见 gate；不保存令牌/密钥。
4. 窗口状态、实际客户区尺寸、内容边框/阴影排除规则、显示器；保存原图，派生裁剪注明矩形。
5. 数据集、选中项、滚动位置、焦点、鼠标位置、时钟、动画阶段、连接状态。
6. 每个参考文件的来源、采集时间、操作步骤、所对应状态。版本无法证实的旧图不能成为新基准。

允许在隔离场景固定动态数据；不修改官方时钟/系统设置来造一致图。无法固定的数据只可逐项说明必要掩码，保存未掩码原图。不能遮住控件、布局、错误提示、模型选项或静态文字来消除差异。

静态资源、官方文档、运行时冲突时先对照版本/模式/gate。较新文档说明的是能力线索，不能自动覆盖较旧固定 App 的实际呈现；无法消歧的动作为未知，不能自行选择“更合理”的设计。

## 3. 界面规格必须覆盖什么

### 3.1 静态结构

- 页面区块顺序、父子关系、分组、层级、固定/滚动部分和 z-index。
- 内容宽度约束、左右/上下锚定、间距、padding、边框、圆角、阴影、对齐。
- 实际中文文案、大小写、标点、空格、省略规则、长文本换行和 tooltip。
- 图标路径/资源来源、尺寸、线宽、颜色、透明度、选中/悬停变体；不以 emoji 替代官方图标。
- 字体、字重、字号、行高、字距、文字基线、代码字体、不同语言 fallback。
- 表格/列表密度、单行高度、缩进、选中范围、滚动条、长列表虚拟化的可见效果。

### 3.2 状态与响应式

每个组件检查 normal、hover、pressed、focus、selected、disabled 及适用的 loading、empty、error、retry、unavailable、permission-denied。异步组件增加 pending、running、cancel-requested、interrupted、completed、failed。

宽窗/窄窗、临近断点的两侧、侧栏折叠、右/底面板开合、多行/长文本/长列表分别采证。只在官方实际支持的尺寸范围测试，不猜测移动端布局。抽屉遮挡、弹层边缘翻转、下拉内部滚动需要独立状态。

### 3.3 呈现时序

为动效记录开始、关键帧、结束：触发→首帧→中间态→稳定态；比较动画属性、耗时、缓动、加载占位、渐隐、自动滚动和焦点变化。时长/容差由官方重复观测建立，不预设任意“300ms”。机器/网络延迟独立记录，不能把服务速度差伪装成动画错误，也不能跳过明显不同的过渡。

## 4. 每个动作的合同

每个可见控件、快捷键、右键项、拖拽区、双击、命令入口都要记录：

```text
前置条件：页面/数据/权限/连接/窗口/焦点/已有草稿
输入：鼠标按钮与次数、键盘组合、文字/文件、拖拽起止、滚动方向
触发范围：哪个区域响应，图标/文字/行背景是否同一点击目标
即时呈现：hover/pressed/禁用/加载/弹层、文案和焦点
业务动作：协议 method/参数、配置作用域、原生 API、实际文件目标
异步呈现：事件序列、进行中、重复操作、取消/离开
最终呈现：成功/失败/拒绝/未知投递、数据显示、焦点和滚动
读回：文件/配置/服务真实值，和界面显示一致
持久化：离开重开/关闭窗口/重启后的结果及生效时机
反向操作：取消/关闭/撤销/恢复，按官方实际能力
验证：双方同一序列、明确断言、证据路径、实际构建
```

“按钮可点击”“toast 出现”“函数存在”“接口没报错”均不是完整动作结果。无法从静态资料得到预期的字段必须继续采证。

## 5. 所有异步动作的共用用例

对适用动作逐项实例化，不能仅复制本表当成已测：

| ID 后缀 | 操作序列 | 必验结果 |
|---|---|---|
| N01 | 正常执行一次 | 请求/通知/数据读回/最终 UI 对应 |
| N02 | 无数据/空输入 | 官方空态、禁用/提示，不创建假结果 |
| N03 | 连点/重复按键 | 是否幂等、请求次数、无重复消息/资源 |
| N04 | 发送中切 A→B，旧 A 响应晚到 | B 的数据/草稿/状态/焦点不被污染 |
| N05 | A→B→A，新 A 读取早于旧 A 返回 | 只接纳当前代次/当前身份的数据 |
| N06 | 执行失败/权限拒绝/数据丢失 | 可见错误、真实状态、原稿和重试入口 |
| N07 | 网络断开/服务退出/重连 | 状态不假成功，未知投递不盲目重发 |
| N08 | 取消/中断请求返回但完成通知未到 | 不提前显示已结束或已完成 |
| N09 | 保存→离开→重开→退出→重启 | 实际持久化、生效时机与官方一致 |
| N10 | 关闭面板/窗口后重开 | 监听/PTY/定时器的释放或保留与产品语义一致 |
| N11 | 不同入口执行同一动作 | 参数、状态变化、焦点与结果一致，无双重处理 |
| N12 | 迟到/重复通知、最终快照与增量重叠 | 无重复内容或状态倒退；已知协议歧义明确登记 |

故障注入用明确的测试适配层/隔离服务，不能写进产品主路径假装真实失败或成功。回放样本必须脱敏并标出来源与覆盖边界。

## 6. 视觉验收操作

### 6.1 采图

1. 确认 G0 环境与等价数据；重置 scroll/focus/mouse/菜单状态。
2. 将双方窗口设为相同实际客户区与缩放，记录方法；不得拉伸截图。
3. 等待相同稳定状态或对应动画关键帧，分别保留原图和元数据。
4. 保存官方→实际的透明叠加图、绝对差图，按标题栏/侧栏/主区/弹层分 ROI 统计。
5. 对主要控件额外记录 bbox、中心/边距和文字基线；不能仅用整图相似度。

### 6.2 判定

- 关键几何锚点：每个位置/尺寸目标差不超过 1 物理像素。任何越界都要指向差异 ID，不能用平均误差抵消。
- 颜色/图标/文本/阴影：保留实际像素差和采样值；文字内容、字体回退、图标、圆角不同均为差异。全图像素差率不设可被“大背景”稀释的单一通过门槛。
- 字体抗锯齿、GPU/系统栅格化残余：先证明字体/几何/颜色一致，再单独列 ROI、差值、环境原因和用户是否接受；未经确认不剔除。
- 动态内容：所有掩码有 ID/矩形/原因，标明影响覆盖范围；全图/ROI同时报告原始与掩码后结果。
- 视觉评分仅用于排序修复；visual-verdict 90+ 不代替这些条件。没有对应参考图时记“不可评分/待采证”。
- 参考图是固定官方输入；测试失败时禁止把本项目输出改名为官方参考，或无新官方证据就刷新 baseline。

## 7. 原生、键盘和输入法验收

- 标题栏拖动及按钮点击，最小化/还原/最大化，窗口缩放和窄窗，必要多显示器 DPI。
- 所有可交互元素的 Tab/Shift+Tab 顺序、focus ring、Enter/Space、Escape、弹层关闭焦点返回。
- 菜单方向键、滑块和编辑器/终端按键各自作用域，不被全局快捷键抢占。
- Windows 中文输入法真实候选：输入拼音→候选翻页/选字→Enter 上屏→确认输入仍在→再次 Enter 发送；同时观察 UI 与实际请求次数。组合事件回放另记。
- 文件选择、拖入、剪贴板、shell/URL 打开、系统通知及热键窗口按实际页面范围验证。
- 底层协议可执行不等于 Tauri 权限已授予；浏览器通过不等于 EXE 通过。

## 8. 自动化落地顺序，不预装新依赖

1. 保留现有静态脚本，给它们标注实际能力；审计名称/日志是否夸大结论。重命名须保持入口同步，不为计划阶段修改测试代码。
2. 使用现有 TypeScript/Node 执行真实函数和状态回放；必要时补实际组件/浏览器动作检查。测试使用独立预期，避免断言只镜像实现。
3. 使用当前已授权浏览器/原生工具测 UI。工具不可用时提供用户可复现步骤与结果记录，留为待执行，不能伪称自动通过。
4. 视觉工具先检查已有环境能否读 PNG、叠加与测像素；若需要新依赖/安装则列缺口和候选方案，由用户明确授权后引入。
5. 为高风险动作保留真实服务测试：隔离工作区/测试账号、写后独立读回、数据与资源清理。外部消息/发布/费用/权限变更需要明确范围授权。

### 8.1 如何淘汰“自证式测试”

示例：文件保存原用例只断言源文本含 ctrlKey 和字符串 s。升级用例必须真实编辑、按 Ctrl+S，再由独立文件读取确认磁盘字节；让保存 handler 临时不执行时此用例必须失败。原结构检查可留下，但不计入保存功能已通过。

模型菜单同理：实际按 ArrowDown 后读 activeElement 和菜单可见性；Escape 后验证焦点返回，不能只查源码含 Escape/stopPropagation。

## 9. 构建与源码身份

每次原生交付记录：HEAD、所有未提交产品差异与未跟踪源码哈希、lockfile/config、构建命令、开始/结束时间、退出码、实际目标路径、EXE SHA-256、测试启动路径。若工作树有其他代理同时修改，先固定快照再构建，避免构建过程中版本漂移。

确认 `npm run build` 生成最新 dist，原生构建配置指向此 dist；手工 cargo build 不会自动替代 beforeBuildCommand，须显式证明前端先构建。不能根据某个旧 EXE 时间猜它包含新代码。

默认检查见 AGENTS.md：聚焦回归→类型/构建→完整标准脚本→适用 Rust 测试→原生/视觉。`-Fast` 不含协议；automations 过滤不等于全 Rust。保留真实退出码与失败日志。纯文档修改不需要运行产品构建。

## 10. 阻塞与问题分级

| 级别 | 示例 | 放行规则 |
|---|---|---|
| P0 | 数据丢失、串会话、重复执行、权限越界、假成功 | 立即停止相关路径，先复现/修复；不得交付为可用 |
| P1 | 主要动作错误、布局/页面结构显著不同、菜单缺项、原生路径不可用 | 当前单元不进入用户验收为完成 |
| P2 | 间距/文字/图标/焦点/动效差异 | 严格 1:1 仍须修复；不得当作可自动忽略的小问题 |
| BLOCKED | 缺官方参考、认证、能力、服务、许可或工具 | 明确受影响用例和解除条件，不计通过 |

用户可接受某个限定范围，但必须记录“降级接受，非严格 1:1”、对应差异和影响。执行器不得自行批准自己的例外。
