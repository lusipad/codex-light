## 发布合同

计划应用版本 0.2.0、标签 `v0.2.0-preview.1`，GitHub 标为 prerelease。仓库原 CI 的 workflow_dispatch 只有 create_release，没有显式 tag，须先修复手动发布到确切标签/提交及自定义说明的能力。

1. 所有阶段变更先定向验证，再完整非 Fast 标准检查、完整 Rust 回归及最终原生构建；只对冻结的最终产品构建，留下源与产物 SHA。
2. CI 加入本批生产前端回放，保留 SDK、全库 Rust 与原生打包；缺主 EXE/安装包必须失败。发布说明声明差异及未测，附可验证的资产哈希和主题许可。
3. 推送 master 后，显式派发同 ref 的发布工作流，复用现有 concurrency 取消冗余分支运行；等待最终 CI 成功及实际 Release/资产存在，不能只报告 push 成功。
4. GitHub 连接器没有 Release 创建/派发接口，使用已配置 gh CLI 与现有 Actions。只发布本项目当前提交，不上传 `.ref`、`.omx`、用户配置或私密数据。

官方配对像素、原生 GUI/IME/账号 gate 与用户逐页验收分别记录；缺证保持未完成。预览发布成功后继续剩余页面，不能因此将全目标 complete。

集成检查、浏览器证据、原生构建及实际发布终态持续记录在[E阶段验收记录](acceptance/ALL-PAGES-E-20261106.md)，各页单元记录保留自身适配差异。
