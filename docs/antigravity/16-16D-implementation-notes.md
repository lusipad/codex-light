# 16.16D 实施记录

计划：[固定提交比较合同](specs/16-16D-pinned-comparison.md)。当前开发中，不作为整页或1:1验收。

## 决策与假设

- 保持：全PR比较使用merge-base→head，固定三SHA直到显式刷新；来源为固定revision-tab原文，可信度高。
- 保持：刷新失败保留旧快照，账号/提供商失效立即隐藏旧内容；用生产组件回放验证，真实账号服务另验。
- 适配：用宿主snapshotId绑定真实账号/PR/三SHA，渲染层不能提供可信账号或任意比较；Electron查询缓存适配为Tauri宿主缓存，不复制包代码。
- 保持：无完整commits字段不伪造空列表；HTTP读取的完整schema仍未实测。错误/不可用与成功空diff必须分开。
- UI先接固定比较和提交选择；共享token与现有表单样式复用，不因缺官方配对图宣称像素一致。

## 验证顺序

1. 宿主固定服务/请求身份/快照归属/取消回归，真实测试返回→前端解析贯通。
2. 前端生产组件回归刷新失败保留、切提交失败不串内容、账号切换与取消晚到、root禁选。
3. 类型检查、前端构建及标准检查；阶段结束再冻结输入、原生打包和提交。

## 偏离与发现

- 直接读raw发现root条目禁用；旧合同仅描述内部fallback，已修正为实际可操作入口。不把内部分支当可达UI。
- 不能为简化而每次切提交重新跟随最新PR快照：PR已推进时，旧固定比较仍须可读。刷新是独立显式动作。
- 后续若真实服务schema与已取证消费不一致，拒绝不完整结果并记录，不捏造接口/成功状态；无破坏性迁移或未知能力注入。
- 浏览器发现网络错误中的connection文本被账号失效正则误判；已改为机器错误码/明确中文权限文案判定，旧变体退出1、修复后生产组件回归及浏览器复验通过。修复发生在完整标准的无关Rust环境专项期间，受影响前端检查尚未执行；保留修复前/最终输入清单。
- 完整文件内容接口已具备，当前页面仍为线性差异与提交选择。尚未把完整文件展开、官方菜单/差异结构或像素标为完成。
- 复核发现bootstrap 401/403在provider入口被丢弃机器码，导致无法清掉失权快照；现保留 `code: message` 并复用已有同格式出口。增加实际Rust错误字符串→生产组件回放，涵盖401/403/network；另覆盖实例不符/连接无效中文出口。完整标准快照与最后定向修复分别登记，最终原生包使用修复后输入。

## 待核验
