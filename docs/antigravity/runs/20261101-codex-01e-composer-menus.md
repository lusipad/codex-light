# 01E Composer 菜单：成组键盘与关闭合同

## 修改前调研

沿用固定 Windows 候选 26.928.21956 / build 12404，本轮进入项目、执行位置、分支、附件与权限菜单的主要键盘路径。前序官方/原生/像素欠项保留，不把推进当作验收。

重新核验 `.ref/scratch/files/app-primary.js` SHA-256 为 `B678C26A3CE9D0B4B30C96BD181CAA862F46CA26E0889AFB2CE618E1CF8300EB`：

- `kAt` @2217014：首页项目选择器，共享 `bY` 搜索/条目组件，有开关、关闭和选择回调。
- `qet` @1127347 / `Jet` @1127664：项目搜索使用 command root 与自动聚焦的 input，搜索由调用者控制。
- `VDt` @2127126 附近 / `Xet` @1128874：项目项有选择回调、disabled 与当前选中标记。
- 本仓库 `ModelSelector` 已有上下方向键展开、Home/End、Escape 返回触发器和滑块键位保护；其他 Composer 菜单多数仍是仅绑定 onClick 的 div。`HOME-SPEC.md` A26/A27 要求菜单键盘导航、关闭和不抢占编辑器输入。

上述静态源码证明组件与选择合同，不证明固定官方在本机的全部焦点时序。以下为本项目补齐可操作性的实现合同，精确官方焦点与像素仍待对照。

## 本轮开发范围

复用既有 `openMenu`、菜单样式和真实动作回调；同一组件内共用键盘处理，不新建组件或依赖，不改后端协议。项目补搜索；项目/执行位置/分支/附件条目改为原生 button；权限复用同组导航。模型保留专用滑块键盘逻辑。

| ID | 操作 | 预期 |
|---|---|---|
| CK01 | 菜单触发器 ArrowDown / ArrowUp | 展开菜单，分别聚焦首/末可操作控件，触发器声明展开状态 |
| CK02 | 菜单方向键、Home、End | 在当前菜单可用控件中导航，焦点滚入可见区域，不触发全局业务动作 |
| CK03 | Escape | 关闭当前菜单并回到对应触发器，组合输入 Escape 不抢占 |
| CK04 | Tab / Shift+Tab、点击 Composer 外 | 关闭菜单；Tab 可以离开，外点不抢回鼠标目标的焦点 |
| CK05 | 项目搜索和选择 | 根据名称/路径过滤，不修改选中值；选择只调用共享选择回调一次 |
| CK06 | 分支新建输入 Home/End、IME Enter | 保持光标编辑语义；输入法选字不创建分支 |
| CK07 | 选择项目、位置、附件、权限条目 | 鼠标或原生键盘激活同一回调；关闭后有明确焦点去向 |
| CK08 | 模型菜单和 textarea | 不被新增通用菜单导航处理器抢占；已有模型/发送回归保持通过 |

生产组件回归先复现缺少语义/键盘入口，再实施；实际浏览器补方向键、Escape、Tab、权限选择和项目搜索。真实目录选择、Worktree 创建与真实权限授予不因键盘测试而自动执行。

## 浏览器发现的定位缺口（修改样式前）

方向键已经打开菜单后，浏览器观察到执行位置菜单向下展开，末项越出窗口底部。复查同一官方 chunk：`SY` @1134434 附近与 `kAt` @2228032 附近均明确 `side: top`，而当前 `.composer-popover-menu.top-left` 使用 `top: calc(100% + 6px)`。本轮将其改为触发器上方，并按实际触发器位置限制可用高度、横向碰边；保留已有菜单间距数值，不从不同场景截图反推新尺寸。仅修正语义 button 的样式继承和可见焦点，不重做主题。

同组模型检查发现 `handleMenuKeys` 的 Escape 未保护 IME，CK08 先复现组合输入 Escape 关闭菜单，再补与其他输入一致的组合标记判断；保留推理滑块原生方向键。不改模型能力归一或权限授予映射。项目空搜索结果使用同版本中文资源 `composer.localCwdDropdown.noProjectsFound`（“未找到项目”），不构造假列表。

## 实施与验证结果

- CK01 修改前失败：项目按钮没有 `aria-haspopup`，也没有方向键入口。修复后 CK01–CK07 执行完整生产 Composer 组件，覆盖五组触发器首/末焦点、方向循环、Home/End、IME Escape、Tab、过滤和单次选择；分支输入法 Enter 不创建分支。
- CK08 修改前复现模型菜单 IME Escape 误关闭，修复后两种组合标记、普通 Escape 与推理滑块原生方向键通过。继续保留专用模型处理器，不将滑块混入新的通用导航。
- 仅复用 `openMenu`、现有真实动作回调、菜单样式与模型能力归一；统一触发器 ref 替换本次已无用途的权限专用 ref。没有新增组件、依赖、后端调用或权限。
