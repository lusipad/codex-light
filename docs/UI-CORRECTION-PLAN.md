## 5. 验收顺序与交付格式

先区域和结构，再动作与状态，最后像素；后端回归贯穿保留。不能在整体布局尚不一致时仅调整圆角和颜色。

每页交付必须同时提供：

- 官方参考、对应源码构建的实际图及并排/叠加/差异；相同客户区、主题、语言、DPI、缩放和等价数据。缺配对条件则列未验证，不评分、不称1px通过。
- 一张控件清单：官方有/当前有/结论/证据；“当前多出”与“官方缺失”均不能省略。
- 动作序列的预期与实际、适用回归退出码；验证原来的真实操作仍有效，而非只测试新DOM结构。
- 当前构建标识、原生鼠标/键盘/IME/窗口结果、剩余差异和用户结论。浏览器回放不等价原生验收。

进度分别记为**功能实现、结构对照、交互对照、像素对照、原生验证、用户验收**，不用一个“自验完成”覆盖全部。历史记录保留，但旧PASS不得自动迁移到新构建或新官方版本。
