# 整页复刻执行计划

制定日期为 2026-11-15。目标是整个软件可观察功能、交互、数据结果和界面与固定官方 Windows Codex App 一致。本计划取代此前按小增量循环切页的执行顺序，已有功能与历史证据继续保留。阶段提交不计为页面完成。

## 工作方式

主开发线一次只处理一个完整页面。当前页面至少交付完整对照材料与可运行构建后才转入下一页。缺证项不静默略过，先明确取得证据需要的条件。只读调研可提前开展。修复公共组件时回归受影响的页面。

每页的顺序如下。

1. 固定官方版本、包哈希、产品模式、语言、主题、窗口客户区、DPI、应用缩放和账号能力。未知项逐项登记。源码基准与运行时场景不能混用。
2. 实际打开官方页面，采集默认、空、加载、正常、错误以及主要弹层的截图、控件和动作。结合 asar 追踪显示条件与数据来源。输出完整区域树和双向控件清单，既查缺失，也查多出。
3. 定义主流程及适用边界。每个动作记录前置条件、输入、状态转换、可见结果、真实读写、取消、错误、重试和焦点归属。未知分支不凭理解实现。
4. 先修整页布局、入口与层级，再补全主动作和状态，最后校准尺寸、文字、图标、颜色与弹层。复用真实服务和既有逻辑，不把诊断信息当普通页面内容。
5. 冻结源码后统一验证。运行相关回归、类型检查、构建、适用协议与 Rust 检查。使用同一构建完成原生操作和宽窄窗验证，避免对每个小控件重复打包。
6. 输出同条件官方图、实际图、叠加或差异图、锚点测量、动作结果和遗留清单。关键锚点目标偏差不超过 1 个物理像素。缺配对条件则保留未验，不给相似度分数。
7. 交付构建和用户验收步骤。只有用户明确确认才写“已验收”。适合保存的开发节点仍可阶段提交，但页面状态保持未完成。

## 证据与进度

每页只维护一个整页主清单，历史子阶段文档作为证据索引。

- 区域与动作合同放在 `docs/antigravity/specs/<页号>-whole-*.md`。
- 官方、实际、差异、环境、来源与构建清单放在 `.ref/parity/<页号>/whole-page/`。
- 整页结果与用户验收放在 `docs/antigravity/acceptance/<页号>-whole-*.md`。
- 状态分为取证中、开发中、自验中、待用户验收、已验收，另列外部阻塞。当前全软件仍未验收。

不设没有依据的完成百分比和日期承诺。每次汇报说明整页清单关闭了哪些缺陷、哪些仍未关闭，以及下一步验证对象。
