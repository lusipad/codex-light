## 1. 范围与执行约定

- 默认基准为 Windows、中文、100% 应用缩放。开始时记录官方版本/build、系统 DPI、窗口客户区尺寸、主题、账号能力与数据场景；版本升级时登记变化，不混用不同版本截图。
- 先完成每页功能文档调研，再修改代码。已有调研是线索，历史“完成”结论不直接继承。
- 每次只推进一个验收单元。公共外壳先验收，后续页面复用；改动公共组件时回归已通过页面。
- 页面包括所属菜单、弹窗、抽屉、详情、状态和键盘路径。会话、工作面板、设置过大，拆成独立单元。
- 保留已有未提交改动，不借此重构相邻代码；默认不新增依赖。
- 每单元完成后提交可审阅的实现、证据和验收结论，交由用户体验验收。用户反馈关闭后再进入下一单元；无需在调研和正常开发步骤之间反复确认。
- 不承诺未经调研的工期。每页调研结束后记录规模、依赖与预估，再实施。

## 2. 每个单元固定执行流程

| 阶段 | 工作 | 产物与通过条件 |
|---|---|---|
| 调研 | 阅读官方功能文档；只读观察目标 App；核对当前源码和协议 | 功能清单、官方来源、参考截图、实测/代码/推断标签、差距与依赖；无关键歧义后开发 |
| 定义验收 | 列出操作、预期结果、状态和视觉锚点 | 可执行用例与截图场景；每个功能映射真实数据源或能力限制 |
| 开发 | 先完成真实功能链路，再校准结构、样式、焦点和快捷键 | 最小必要改动；不以假数据、固定延时或模拟成功代替功能 |
| 自动验证 | 执行适合改动的类型检查、构建、回归与协议验证 | 实际命令、退出码、失败与警告均有记录；缺陷修复后重验 |
| 视觉验证 | 同环境截图，比较整体、局部与像素差 | 原图、实现截图、叠加/差异图、差距表；每轮修改后重新比较 |

## 3. 开发顺序与逐页范围

### 每页必须使用 asar 证据

asar 作为前端静态实现的主要参照，与官方文档、官方运行时实测共同建立基准。已有提取保存在 `.ref/asar-files/`、`.ref/scratch/`、`.ref/reference/css/`；旧清单仅作索引，不能视为全量或当前版本证明。

每页开发前必须：

1. 校验安装包版本/build 与 SHA-256；记录相关 chunk 的路径和哈希，确认提取文件对应目标版本。只读提取，不修改官方安装包。
2. 从路由追踪页面 chunk、共享组件、菜单/命令注册表、状态分支、配置键、IPC/协议调用及能力门控。若存在 source map 则使用；不存在时不假定能恢复完整源码。
3. 提取适用的 CSS token、选择器、尺寸、间距、字重、圆角、颜色、断点和动画；记录 Electron/Windows/主题/模式条件，不能混用其他变体。
4. 定位实际中文语言包、图标及资源引用；英文 defaultMessage 不能直接充当官方中文文案，资源复用需确认许可条件。
5. 为每项验收行为建立“原始文件/定位片段 → 官方运行时观察 → 我们的代码 → 测试/截图”的对应关系。混淆代码行号不稳定时保存检索锚点和片段哈希。
6. 对未激活分支、实验开关和云端能力标注“静态发现、未实测”；以当前账号可观察行为确认适用性，不通过强开 gate 冒充官方支持。

开发时参考前端结构与行为，在 Tauri 中实现等价平台适配；不直接整包移植 Electron 运行时代码。asar 不能证明服务端内部逻辑、远程下发配置或原生平台行为一致，这些必须用真实运行与协议结果验证。

所有单元初始均为“待调研/复核”。上一轮首页和快捷键工作属于已有实现，尚不等于本计划的用户验收。

## 5. 每页统一验收标准

### 功能与数据

- 所有可见入口能完成对应动作；数据来自真实协议或已明确的本地存储。无固定延时假完成、假回复、假部署。
- 适用的加载、空、正常、错误、重试、无权限、能力不可用、运行中/中断状态均有用例。
- 持久化、返回/前进、重新打开、断连恢复按该页面行为验证。
- 键盘、鼠标、焦点返回、Escape、中文输入法与滚动均可用；没有误触发、数据丢失或控制台未处理异常。
- 破坏性和外部写操作使用隔离数据验证；需要真实付费/发布/不可逆动作时，先准备可审阅结果并明确请求授权。

### 视觉与像素

- 官方与当前使用同客户区像素尺寸、DPI、主题、语言、缩放、数据及状态；不得用不同高度截图直接计算差值后宣称通过。
- 固定至少标准宽窗与窄窗两组尺寸；00 单元记录具体尺寸，后续沿用。
- 对齐标题栏、侧栏、内容区域、页边距、文字基线、控件尺寸、圆角、边框、颜色、阴影、图标与弹层定位。
- 关键几何锚点目标偏差不超过 1 个物理像素；可消除的结构/色彩差异必须修复。字体渲染和抗锯齿差异单独说明并保留差异图，不通过调低阈值掩盖。
- 动画、光标、时间戳等动态区域在对比前固定或在掩码清单中逐项注明。不得屏蔽布局或功能缺陷。
- 使用 visual-verdict 逐轮记录结构化评估；90 分只是迭代参考，不替代像素差证据与用户验收。
